# 과제 08: 최소 비용 신장 트리 알고리즘 비교

가중치 무방향 단순 연결 그래프(정점 50개)에 대해 희소 그래프(간선 100개)와 밀집 그래프(간선 600개)를 생성하고,
**Kruskal(인접 리스트)** 과 **Prim(인접 행렬)** 로 MST를 구해 메모리 사용량과 실행시간을 비교한다.

## 1. 빌드 및 실행

```bash
gcc -O2 -std=c11 -o mst_compare mst_compare.c
./mst_compare           # 실행할 때마다 다른 그래프 생성 (시드 = 현재 시각)
./mst_compare 2026     # 시드를 지정하면 같은 그래프를 재현
./mst_compare 2026 e   # 두 번째 인자를 주면 각 케이스의 MST 간선 목록도 출력
```

기본 출력은 과제의 출력 형식(Case 1~4의 Vertices, Edges, MST Edges, MST Cost, Memory, Execution Time)만 보여 준다.

## 2. 구현 요약

| 항목 | 내용 |
|---|---|
| 그래프 생성 | 랜덤 신장 트리(49개 간선)를 먼저 만들어 연결성을 보장한 뒤, 자기 자신 간선과 중복 간선을 피하며 나머지 간선을 랜덤 추가. 가중치는 1~100의 정수. 생성 후 Union-Find로 연결성을 재검증하고 실패하면 재생성 |
| 동일 그래프 사용 | 희소/밀집 그래프를 각각 한 번만 생성하고, 같은 간선 목록으로 인접 리스트와 인접 행렬을 모두 구성 (Case 1·3, Case 2·4가 같은 그래프) |
| Kruskal | 인접 리스트에서 간선 추출(u < v) → 직접 구현한 힙 정렬(제자리 정렬, 추가 메모리 없음)로 가중치 오름차순 정렬 → Union-Find(경로 압축 + rank)로 사이클 판별 → 49개 선택 시 종료 |
| Prim | 인접 행렬 + `key[]`, `parent[]`, `visited[]` 배열. 매 단계 O(V)로 최소 key 정점을 선택하는 O(V²) 구현. 시작 정점 0 |
| 메모리 측정 | `sizeof`로 직접 계산. 그래프 표현 + 알고리즘 보조 자료구조 + MST 결과 배열 포함, 난수 생성·출력용 메모리는 제외 |
| 시간 측정 | 그래프 생성이 끝난 뒤 MST 알고리즘 호출 직전부터 호출 직후까지 **1회 실행**을 `timespec_get`(ns 단위)으로 측정해 ms로 출력. 4개 케이스 모두 동일한 방법과 단위 사용. Kruskal의 간선 배열 할당/해제는 계산 시간에 포함 |
| 검증 | 시드 1~200으로 실행해 모든 케이스에서 MST 간선 수가 49이고, 출력된 간선 가중치의 합이 MST Cost와 같으며, 같은 그래프의 Kruskal/Prim 비용이 일치함을 확인. 프로그램은 두 알고리즘의 비용이 다르면 종료 코드 1을 반환 |

메모리 계산식 (64비트 환경: `int` 4B, 포인터 8B, `sizeof(Edge)` = 12B, `sizeof(AdjNode)` = 16B)

- Kruskal = 헤드 배열 400 + 노드 16×2E + 간선 배열 12×E + Union-Find 400 + MST 결과 588 = **1,388 + 44E** Byte
- Prim = 행렬 10,000 + key/parent 400 + visited 50 + MST 결과 588 = **11,038** Byte (E와 무관)

## 3. 실행 결과 (seed = 2026)

같은 시드(같은 그래프)로 프로그램을 30회 실행한 결과의 **중앙값**이다. 괄호는 30회 중 최소~최대 범위이다.

| Case | 그래프 | 표현 | 알고리즘 | MST 간선 수 | MST 전체 비용 | 메모리 (Byte) | 실행시간 (ms) |
|---|---|---|---|---|---|---|---|
| 1 | Sparse (E=100) | 인접 리스트 | Kruskal | 49 | 1668 | 5,788 | 0.00736 (0.0071~0.0096) |
| 2 | Dense (E=600) | 인접 리스트 | Kruskal | 49 | 289 | 27,788 | 0.04485 (0.0437~0.0947) |
| 3 | Sparse (E=100) | 인접 행렬 | Prim | 49 | 1668 | 11,038 | 0.01036 (0.0096~0.0369) |
| 4 | Dense (E=600) | 인접 행렬 | Prim | 49 | 289 | 11,038 | 0.02043 (0.0197~0.0247) |

- 같은 그래프에서 Kruskal과 Prim의 MST 비용이 일치했다 (희소 1668, 밀집 289). 선택된 간선의 순서와 구성은 달라질 수 있다.
- 실행시간이 수~수십 μs 수준이라 OS 스케줄링 등에 의한 이상값(최대값)이 가끔 나타난다. 그래서 평균 대신 중앙값을 사용했다.
- 실행 환경과 시드에 따라 수치는 달라진다. 메모리는 구조체 크기(패딩 포함)에 의존한다.

## 4. 분석

### 4.1 희소 그래프와 밀집 그래프에서의 성능 차이

간선이 100개에서 600개로 6배 늘었을 때 Kruskal은 0.0074 ms에서 0.0449 ms로 **약 6.1배** 느려졌다. 간선 수 증가 비율과 거의 같다.
Prim은 0.0104 ms에서 0.0204 ms로 **약 2.0배** 증가했다.
밀집 그래프에서는 Prim이 Kruskal보다 약 2.2배 빨랐고, 희소 그래프에서는 반대로 Kruskal이 Prim보다 약 1.4배 빨랐다.

메모리는 Kruskal이 5,788 B에서 27,788 B로 약 4.8배 늘었지만 Prim은 11,038 B로 변하지 않았다.
즉 Kruskal은 밀도가 높아질수록 시간과 메모리 모두 간선 수에 비례해 커지고, Prim은 메모리가 정점 수로 고정되며 시간 증가도 상대적으로 작았다.

### 4.2 인접 리스트와 인접 행렬의 메모리 사용 차이

인접 리스트는 간선 수에 비례한다. 무방향 그래프는 간선 하나당 노드가 2개(16 B씩) 필요하고,
Kruskal은 정렬용 간선 배열(12 B × E)도 따로 만들기 때문에 총 메모리는 `1,388 + 44E` Byte가 된다.
인접 행렬은 간선이 몇 개든 `V × V × 4 = 10,000` B를 항상 차지한다.

- 희소 그래프(E=100): 리스트 쪽이 5,788 B로, 행렬 쪽 11,038 B의 약 52% 수준이다. 존재하지 않는 간선 대부분을 행렬이 0으로 저장하기 때문이다.
- 밀집 그래프(E=600): 리스트 쪽이 27,788 B로 행렬 쪽의 약 2.5배다. 이 그래프는 가능한 간선 1,225개의 약 49%가 존재해 행렬의 낭비가 줄어든 반면, 리스트는 노드마다 포인터(next)와 패딩을 포함한 16 B를 쓰고 Kruskal이 간선 배열까지 따로 만들기 때문이다.
- 두 표현의 메모리가 같아지는 지점은 `1,388 + 44E = 11,038`에서 E ≈ 219다. 간선이 이보다 적으면 리스트가, 많으면 행렬이 유리하다. 이번 실험의 희소/밀집 두 그래프는 각각 이 경계의 양쪽에 놓여 있었다.

### 4.3 Kruskal과 Prim의 실행 특성 차이

**Kruskal**은 간선 중심 알고리즘이다. 매번 (1) 간선 배열을 할당하고 인접 리스트를 순회해 간선을 추출하며(노드 2E개 방문),
(2) 힙 정렬(O(E log E))로 전체 간선을 정렬한 뒤, (3) 작은 간선부터 Union-Find로 사이클을 검사한다.
49개 간선을 찾으면 3단계는 조기 종료하지만 정렬은 모든 간선에 대해 먼저 끝내야 하므로, 실행시간이 간선 수에 거의 비례해 늘어난다.
밀집 그래프에서는 추출·정렬 대상이 600개로 늘고 7.2 KB의 `malloc`/`free` 비용도 함께 반영된다.

**Prim**은 정점 중심 알고리즘이다. 인접 행렬 버전은 정점을 50번 선택하는 동안 매번 key 배열 전체(50개)를 훑어 최소값을 찾고,
선택한 정점의 행(50칸)을 읽어 key를 갱신한다. 반복 횟수는 약 V² = 2,500으로 간선 수와 무관하게 고정되고, 동적 할당도 없다.
다만 측정 결과에서 밀집 그래프의 시간이 희소 그래프의 약 2배로 늘었는데, 이는 반복 횟수 때문이 아니라 행렬에서 0이 아닌 칸이 늘어
(평균 차수 4 → 24) key 비교와 갱신 분기가 더 자주 실행되기 때문으로 추정한다. 이 원인은 별도 프로파일링으로 확인하지는 않았다.

### 4.4 측정 방식에 따른 주의점

과제 조건대로 MST 계산을 1회만 측정하면 CPU 캐시와 분기 예측기가 아직 준비되지 않은 상태의 시간이 포함된다.
이 프로그램을 개발하는 중에 같은 그래프(seed 2026)에서 알고리즘을 1000회 반복해 평균을 낸 실험도 해 보았는데,
그때는 Case 1~4가 각각 0.0047, 0.0467, 0.0039, 0.0049 ms로 나왔다(이 반복 측정 코드는 최종 제출 코드에 포함하지 않았다).
Kruskal은 단일 측정과 큰 차이가 없었지만 Prim은 단일 측정이 2~4배 느렸다. 즉 Prim 쪽이 초기 실행의 영향을 더 크게 받았고,
그 결과 희소 그래프에서 두 알고리즘의 우열이 단일 측정(Kruskal 우세)과 반복 평균(Prim이 약간 우세)에서 서로 달라졌다.
밀집 그래프에서 Prim이 Kruskal보다 빠르다는 결론은 두 방식 모두에서 같았다.
이 때문에 아래 종합 결론에서는 희소 그래프의 시간 우열은 단정하지 않는다.

### 4.5 그래프 밀도가 각 방법에 미치는 영향 (종합)

| 구분 | 희소 그래프 | 밀집 그래프 |
|---|---|---|
| 메모리 | 리스트 유리 (5,788 B < 11,038 B) | 행렬 유리 (11,038 B < 27,788 B) |
| 시간 | 두 알고리즘 모두 수 μs 수준으로 차이가 작고, 측정 방식에 따라 우열이 바뀜 | Prim이 약 2.2배 빠름 (반복 평균 기준으로는 약 9배) |
| 밀도 증가에 따른 변화 | Kruskal: 시간 약 6배, 메모리 약 4.8배 증가 | Prim: 시간 약 2배 증가, 메모리 불변 |

- **Kruskal + 인접 리스트**는 희소 그래프에서 메모리가 적게 들고 시간도 충분히 짧다. 그러나 밀도가 올라가면 시간과 메모리 모두 간선 수에 비례해 커진다.
- **Prim + 인접 행렬**은 메모리가 정점 수(V²)에만 의존하고, 밀집 그래프에서 시간과 메모리 양쪽에서 가장 안정적이었다. 희소 그래프에서는 빈 칸 때문에 메모리 면에서 불리하다.
- 정리하면, 간선이 적을 때(E ≪ V²)는 간선 중심의 Kruskal과 인접 리스트가 메모리 면에서 적합하고, 간선이 많을 때(E가 V²에 가까울 때)는 정점 중심의 Prim과 인접 행렬이 시간·메모리 모두 적합하다는 일반적인 이론과 이번 실험 결과가 대체로 일치했다.
- 다만 이번 실험은 V=50의 작은 그래프이고 실행시간이 수~수십 μs 수준이라 측정 오차의 비중이 크다. 따라서 케이스 간 큰 차이(밀집 그래프에서 Kruskal이 Prim보다 느림, Kruskal의 시간이 간선 수에 비례해 증가)만 의미 있는 결과로 해석했다.
